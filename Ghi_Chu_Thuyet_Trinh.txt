SLIDE 6 – NODEJS (Dự kiến: 40 giây)
--------------------------------------------------------------------------------
[Lời nói]:
"Node.js là runtime môi trường chạy JavaScript phía server trên nền Google V8 Engine.
Nhờ cơ chế Non-blocking I/O và hướng sự kiện (Event-driven), Node.js có thể xử lý
hàng ngàn kết nối đồng thời từ khách hàng một cách mượt mà.

Trong đồ án, Node.js khởi chạy HTTP Server tại cổng 10000 thông qua file server/src/index.js.
Node.js đóng vai trò điều phối toàn bộ luồng: nhận request từ React, chuyển qua Express xử lý,
gọi Mongoose truy vấn Database, đồng thời phục vụ luôn thư mục build tĩnh client/dist.
Khi deploy lên Render.com, lệnh 'npm run start' sẽ khởi động server Node.js hoạt động 24/7."

SLIDE 7 – CƠ SỞ DỮ LIỆU MONGODB (Dự kiến: 45 giây)
--------------------------------------------------------------------------------
[Lời nói]:
"Về cơ sở dữ liệu, nhóm chọn MongoDB – hệ quản trị CSDL NoSQL lưu trữ dưới dạng Document JSON/BSON.
MongoDB rất phù hợp với bài toán bán hoa vì một mẫu hoa có thể có nhiều kích cỡ (S/M/L) với giá
khác nhau và nhiều ảnh – cấu trúc này lưu trữ dưới dạng mảng lồng nhau (embedded array) rất tự nhiên.

Nhóm sử dụng Mongoose ODM để định nghĩa Schema và Model chặt chẽ.
Cơ sở dữ liệu thực tế gồm 6 Collections chính:
- products: lưu danh mục hoa, giá, biến thể, hình ảnh và số lượng kho.
- users: tài khoản, mật khẩu băm bcrypt, phân quyền customer và admin.
- orders: đơn đặt hàng, chi tiết sản phẩm, hẹn giờ giao, trạng thái thanh toán.
- occasions: các dịp tặng hoa như Sinh nhật, Khai trương, Tình yêu...
- coupons: mã giảm giá với hạn dùng và giá trị đơn tối thiểu.
- settings: thông tin cửa hàng, phí ship và số tài khoản ngân hàng sinh mã VietQR.
Đặc biệt, hệ thống có thiết kế Adapter hỗ trợ linh hoạt cả MongoDB Atlas lẫn Local JSON file."

SLIDE 8 – WEB FRAMEWORK EXPRESS.JS (Dự kiến: 40 giây)
--------------------------------------------------------------------------------
[Lời nói]:
"Express.js là web framework tối giản chạy trên Node.js để xây dựng RESTful API.
Mã nguồn backend được tổ chức routes theo từng module nghiệp vụ riêng biệt:
authRoutes, productRoutes, orderRoutes, adminRoutes và couponRoutes.

Về bảo mật và xử lý dữ liệu, nhóm xây dựng các Middleware chuyên trách:
- Middleware requireAuth giải mã và kiểm tra tính hợp lệ của JWT token trong header.
- Middleware requireAdmin kiểm tra phân quyền tài khoản (role === 'admin').
- Middleware Multer tiếp nhận upload file ảnh hoa từ form, giới hạn tối đa 10 ảnh
  và lưu trữ an toàn vào thư mục server/uploads/products/."

III. GỢI Ý TRẢ LỜI CÁC CÂU HỎI PHẢN BIỆN CỦA GIẢNG VIÊN (Q&A)
================================================================================

Câu 1: JSX khác HTML thuần như thế nào?
Trả lời:
"Dạ thưa thầy, JSX là cú pháp mở rộng của JavaScript, trông giống HTML nhưng có thể nhúng trực tiếp
các biểu thức JavaScript thông qua cặp dấu ngoặc nhọn {}. Trong JSX, các thuộc tính dùng quy tắc camelCase
(ví dụ className thay vì class, onClick thay vì onclick). Công cụ Vite (Babel) sẽ biên dịch JSX thành
React.createElement() trước khi trình duyệt thực thi."

Câu 2: Cơ chế quản lý State của giỏ hàng (Zustand) hoạt động ra sao?
Trả lời:
"Dạ, nhóm dùng Zustand với middleware persist trong file useCartStore.js. Khi người dùng thêm hoặc sửa số lượng hoa,
Zustand cập nhật state trong bộ nhớ RAM đồng thời tự động đồng bộ hóa xuống LocalStorage của trình duyệt.
Nhờ đó, ngay cả khi khách đóng tab hoặc tải lại trang thì giỏ hàng vẫn được bảo toàn nguyên vẹn."

Câu 3: Phân quyền giữa User và Admin được bảo mật như thế nào ở Backend?
Trả lời:
"Dạ, hệ thống áp dụng bảo mật 2 lớp:
1. Khi đăng nhập thành công, server cấp JWT token có payload chứa userId và role ('customer' hoặc 'admin').
2. Ở các route quản trị (/api/admin/*), request bắt buộc phải đi qua 2 middleware liên tiếp:
   - requireAuth: kiểm tra token hợp lệ bằng jwt.verify().
   - requireAdmin: kiểm tra req.user.role === 'admin'. Nếu không phải admin thì trả về mã lỗi 403 Forbidden."

Câu 4: Dual-mode Database Adapter hoạt động như thế nào?
Trả lời:
"Dạ, nhóm thiết kế theo mẫu Adapter Pattern:
- Nếu biến môi trường DB_MODE=mongo: hệ thống kết nối MongoDB Atlas qua Mongoose Model.
- Nếu DB_MODE=local: hệ thống đọc ghi dữ liệu trên các file JSON trong thư mục server/data/.
Cả hai adapter đều tuân thủ cùng một interface phương thức (.findAll, .findById, .create, .update, .delete),
do đó toàn bộ tầng Controller nghiệp vụ không cần thay đổi khi chuyển đổi CSDL."
